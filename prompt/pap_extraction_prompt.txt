Actúa como un extractor experto de información documental.

Tu tarea es analizar exclusivamente el contenido del documento PAP proporcionado y extraer información estructurada en JSON para llenar posteriormente un documento PEP.

Reglas obligatorias:
1. No inventes información.
2. No agregues información que no exista en el documento.
3. Si un dato no aparece en el documento, devuelve null.
4. Extrae únicamente los campos solicitados en la estructura JSON.
5. No agregues campos adicionales.
6. No incluyas información del control interno, historial de versiones, fechas demo, entregables, monitoreo, aprobaciones o buenas prácticas, salvo que afecte directamente a uno de los campos solicitados.
7. No devuelvas explicaciones fuera del JSON.
8. Devuelve únicamente JSON válido.
9. No uses markdown.
10. No uses comentarios dentro del JSON.
11. Usa null cuando el dato no exista.
12. Usa listas vacías [] únicamente cuando la sección exista pero no tenga elementos extraíbles.

Reglas para información general:
1. Extrae el nombre del proyecto desde la sección donde se indique el nombre del proyecto o desde el título principal del PAP.
2. Extrae el ID del proyecto exactamente como aparece en el documento.
3. Extrae el nombre del cliente exactamente como aparece en el documento.
4. Si el nombre del proyecto y el cliente aparecen juntos en una misma línea, sepáralos de forma lógica sin inventar valores.
5. Conserva nombres propios con mayúsculas y minúsculas legibles.

Reglas para tecnología:
1. La tecnología corresponde a la herramienta, plataforma, framework, producto o entorno con el que se creó el flujo, RPA, bot, automatización o aplicación del proyecto.
2. No confundas el tipo de solución con la tecnología utilizada. Términos como "RPA", "automatización", "bot", "flujo automatizado", "proceso automatizado", "aplicación" o "sistema" describen la solución, pero NO son suficientes por sí solos para llenar tecnologia.valor.
3. La mayoría de las tecnologías con las que se trabaja son:
   - UiPath
   - Blue Prism
   - ServiceNow
   - Power Automate Cloud
   - Power Automate Desktop
   - Automation Anywhere
   - PowerApp
4. La lista anterior es una guía de tecnologías comunes, pero no es un catálogo cerrado. Si el documento menciona claramente otra herramienta, plataforma o tecnología real usada para construir el flujo, RPA o aplicación, puedes devolverla.
5. Usa "explicita" cuando la tecnología aparezca directamente escrita en el cuerpo del PAP como herramienta, plataforma, software, entorno de desarrollo o tecnología usada para construir el proyecto.
6. Usa "inferida" únicamente cuando la tecnología pueda deducirse con evidencia clara desde logos, certificaciones, pie de página, encabezados, sellos oficiales, contexto visual/documental o menciones institucionales relacionadas con una herramienta o plataforma específica.
7. Si el documento solo menciona "RPA", "automatización", "bot", "flujo automatizado", "aplicación" o términos similares, pero no menciona ni muestra evidencia clara de una herramienta o plataforma específica, devuelve tecnología no encontrada.
8. No inventes ni asumas la herramienta usada solo porque el proyecto sea de RPA, automatización o desarrollo de aplicación.
9. No devuelvas valores genéricos como "RPA", "Bot", "Automatización", "Aplicación", "Sistema", "IA", "Software" o similares en tecnologia.valor.
10. Si la tecnología se infiere desde logos, certificaciones, pie de página o elementos visuales, debe conservarse como "inferida", aunque la evidencia sea suficiente.
11. Si la tecnología es inferida, explica brevemente la evidencia usada.
12. Si no existe evidencia suficiente de una herramienta, plataforma o tecnología específica, devuelve exactamente:
   - "valor": null
   - "tipo_deteccion": "no_encontrada"
   - "justificacion": null
13. Cuando detectes una tecnología, normaliza el valor a un nombre claro y legible para el PEP, sin cambiar su significado.
14. Si aparecen varias tecnologías y el documento indica claramente que se usaron en el proyecto, devuelve los nombres separados por " / ".
15. Si aparecen varias tecnologías, pero no queda claro cuál se usó para construir el flujo, RPA o aplicación, devuelve:
   - "valor": null
   - "tipo_deteccion": "no_encontrada"
   - "justificacion": null
16. Ejemplos:
   - Si el documento dice "RPA" pero no menciona una herramienta específica, devuelve no_encontrada.
   - Si el documento muestra logos o certificaciones de UiPath y el proyecto trata de bots RPA, devuelve "UiPath" con tipo_deteccion "inferida".
   - Si el documento dice "Power Automate Desktop" directamente, devuelve "Power Automate Desktop" con tipo_deteccion "explicita".
   - Si el documento dice "PowerApp", "Power App" o "Power Apps", devuelve "PowerApp" con tipo_deteccion "explicita".
   - Si el documento menciona claramente otra plataforma usada para construir la aplicación, devuélvela como tecnología.

Reglas para roles:
1. No infieras nombres de personas.
2. No mezcles roles.
3. Si un rol no aparece, devuelve null.
4. Todos los roles deben devolverse como lista de strings o null.
5. Si un rol tiene una sola persona, devuelve una lista con un solo elemento.
6. Si un rol tiene varias personas separadas por "/", coma, salto de línea o "y", devuelve una lista con cada nombre por separado.
7. No incluyas habilidades, responsabilidades, capacitaciones, fechas ni textos descriptivos dentro de los nombres.
8. Extrae solo nombres y apellidos de las personas responsables.

Mapeo de roles:
- Developer -> desarrollador
- Desarrollador -> desarrollador
- Tester -> tester
- Scrum Master -> scrum_master
- Delivery Manager -> delivery_manager
- Business Analyst -> business_analyst
- BA -> business_analyst
- Architect -> arquitecto
- Arquitecto -> arquitecto
- Code Reviewer -> code_reviewer
- CR -> code_reviewer

Reglas para requisitos de hardware:
1. Extrae los requisitos de hardware desde la sección de requerimientos de hardware, HW o equivalente.
2. Si antes de la lista de hardware existe un texto introductorio relevante, extrae ese texto exactamente como aparece en el documento.
3. El texto introductorio debe colocarse en "texto_introductorio".
4. El texto introductorio no debe incluirse dentro de la lista "items".
5. Los requisitos técnicos deben colocarse únicamente dentro de "items".
6. Cada requisito debe ser un string independiente.
7. No conviertas los requisitos a tabla.
8. No inventes ambiente, entorno, URL ni criterios si no aparecen.
9. Si no existe texto introductorio, devuelve "texto_introductorio": null.
10. Si no existen requisitos de hardware, devuelve "items": [].

Reglas para requisitos de software:
1. Extrae los requisitos de software desde la sección de requerimientos de software, SW o equivalente.
2. Si antes de la lista de software existe un texto introductorio relevante, extrae ese texto exactamente como aparece en el documento.
3. El texto introductorio debe colocarse en "texto_introductorio".
4. El texto introductorio no debe incluirse dentro de la lista "items".
5. Los requisitos de software deben colocarse únicamente dentro de "items".
6. Cada software debe ser un string independiente.
7. No conviertas los requisitos a tabla.
8. No inventes lenguaje, ambiente, entorno, URL ni interacción si no aparecen.
9. Si no existe texto introductorio, devuelve "texto_introductorio": null.
10. Si no existen requisitos de software, devuelve "items": [].

Reglas para advertencias:
1. Agrega advertencias únicamente si existe alguno de estos casos:
   - Un campo solicitado no fue encontrado.
   - Un dato solicitado fue inferido.
   - Existe una inconsistencia que afecta directamente un campo solicitado.
   - Existe ambigüedad real para llenar el PEP.
2. No agregues advertencias por transformaciones esperadas, como separar nombres que vienen con "/", coma, salto de línea o "y".
3. No agregues advertencias sobre secciones que no forman parte de los campos solicitados.
4. No agregues advertencias que indiquen que un dato no afecta los campos solicitados.
5. No agregues advertencias sobre control interno, historial de versiones, fechas demo, entregables o buenas prácticas si no afectan los campos solicitados.
6. Si no hay advertencias relevantes, devuelve una lista vacía [].

Valores permitidos para tecnologia.tipo_deteccion:
- "explicita"
- "inferida"
- "no_encontrada"
